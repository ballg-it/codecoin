## ภาพรวมโปรเจค

CodeCoin คือบอร์ดเกมเพื่อการศึกษา (โปรเจคจบ) ดัดแปลงจาก Monopoly ผสมระบบ QR Code ครอบคลุม 4 วิชา: Coding, Microsoft Office, Graphic Design, การประกอบคอมพิวเตอร์

ผู้เล่นใช้มือถือสแกน QR บนการ์ด/กระดานเพื่อ:
- **ช่องทรัพย์สิน** — อ่านเนื้อหาสั้น + ตอบควิซ ตอบถูกได้ส่วนลด 20%
- **ช่องเหตุการณ์** — สุ่มการ์ดเหตุการณ์ตามโซน (weighted random)
- **ช่องติดบั๊ก (Bug Jam)** — แก้โจทย์ debug จับเวลาเพื่อออกจาก "คุก" ฟรี
- **อัปเกรดทรัพย์สิน** — ตอบคำถามระดับสูงขึ้น (L2 ชำนาญ / L3 ผู้เชี่ยวชาญ) ปลดล็อกค่าเช่าใหม่

ทั้งหมดเป็น static site — ไม่ต้องติดตั้งแอป ไม่ต้อง login โหลดเร็ว host ฟรีบน GitHub Pages

## งานที่ทำเสร็จแล้ว (ตามลำดับเวลา)

### 1. ระบบเว็บหลัก (ต่อยอดจาก handoff)
- แยกข้อมูลเกมออกจากโค้ดเป็น `data.json` — เว็บ fetch ตอนโหลด มี fallback ในตัว (โหลดพลาด → ใช้ข้อมูลสำรอง + แถบเตือน) และซ่อนแถว `DRAFT` อัตโนมัติ
- ระบบอัปเกรด: route `?space={id}&upgrade={level}` เข้าจากปุ่มในหน้าช่องทรัพย์สิน (ใช้ QR ใบเดิม)
- เมนูทดสอบจัดกลุ่มตามโซน มีสีประจำโซนกำกับ
- hook เก็บสถิติ (`CONFIG.log_url`) — พัฒนาเป็นระบบเต็มแล้วใน REV 2.5 ดูหัวข้อ 10

### 2. Pipeline ข้อมูลจากทีม content
- `scripts/build_data.py` แปลง Excel → data.json: rent 4 คอลัมน์ → array, เฉลย a/b/c/d → index, ตรวจ space_id อ้างอิง, ตรวจเฉลยชี้ตัวเลือกว่าง
- workflow: แก้ `codecoin_database.xlsx` → `py scripts/build_data.py` → push (เว็บอัปเดตเองใน ~1 นาที)

### 3. QR และสื่อสิ่งพิมพ์
- `scripts/gen_qr.py` สร้าง QR 21 ใบจาก data.json (16 ทรัพย์สิน + event 4 โซน + bugjam) ลงที่ `print/qr_output/`
- การ์ดทรัพย์สิน `print/codecoin_cards_rev3_1.html`: QR ฝังเป็น data URI (เปิดไฟล์เดี่ยวได้ ไม่ต้องมีโฟลเดอร์ `qr_output/`) ค่าเช่า/ค่าอัปเกรดจริงจากฐานข้อมูล — ใช้ไฟล์นี้ export เป็น PDF ใน `print/Final/` ซึ่งเป็นตัวที่ส่งโรงพิมพ์จริง
- ผังกระดาน: ตัวจริงคือ **`print/Final/CodeCoin-Board-50x50-Final1.pdf` (REV 2.4)** — ไฟล์ SVG รุ่นเก่า (`codecoin_board_rev2_3_canva.html`) ลบทิ้งแล้ว

### 4. Deploy
- GitHub Pages จาก branch `main` — push แล้วเว็บอัปเดตเองใน ~1 นาที
- PR #1 (ลิงก์เว็บจริงใน README) merge แล้ว

### 5. ฟีเจอร์เกมบนเว็บ (REV 1.2 → 2.2)
- **ระบบเดิมพันควิซ** (หน้าซื้อทรัพย์สิน): "ตอบธรรมดา" ถูกลด 20% / "มั่นใจ! 🔥" ถูกลด 40% ผิดจ่ายเพิ่ม 10% — ตัวเลขแก้ได้ใน `CONFIG.bet_confident`, log สถิติแยก kind
- **เสียง + visual feedback**: Web Audio ล้วนไม่มีไฟล์เสียง (ติ๊กนับถอยหลังเร่งท้าย 5 วิ, ติ๊งตอบถูก, fanfare โหมดมั่นใจ, โทนต่ำตอบผิด, buzzer หมดเวลา, ฉลองอัปเกรด) + แฟลชเขียว/แดง/ทอง, confetti, ปุ่ม mute ลอย — เสียงปลดล็อกจาก gesture แรกตามนโยบาย browser มือถือ
- **Event แบบ speed** (แข่งตอบเร็วรอบโต๊ะ): โชว์คำถามสุ่มให้ทุกคนแข่งตอบปากเปล่า คนถือมือถือกดปุ่ม "ผู้เล่น 1–4" บันทึกผู้ชนะ → รับรางวัลตาม effect, timer 15 วิ หมดเวลา = ไม่มีใครได้ — ไม่ใช่ multiplayer จริง ไม่มี account/session (เงินจดบนกระดาษนอกเว็บ)
- **Bug Jam เลือกระดับ + hint**: เลือก "ง่าย" (ออกฟรี) หรือ "ยาก 💎" (ถูก = ออกฟรี + โบนัส 300) ก่อนสุ่มโจทย์ / ปุ่ม 💡 ดู hint กดได้ครั้งเดียว — ระดับยากกดแล้วโบนัสเหลือ 150 / ไม่มีโจทย์ hard = ปุ่มยาก disabled พร้อมข้อความ (ตอนนี้รอทีม content เติมแถว hard)
- `build_data.py` รองรับคอลัมน์ใหม่ `difficulty`/`hint` ของชีต bugjam แบบ backward-compatible (ไฟล์เก่าไม่มีคอลัมน์ = easy/ไม่มี hint)
- **สุ่มผลแก้บั๊ก (Fail Roulette, REV 1.6)**: ผูกกับเลนเดิมพัน — "มั่นใจ! + ตอบผิด" บังคับหมุนวงล้อ 7 ช่อง (mult 0.4–1.6 เทียบราคาช่อง) แทนจ่าย flat ธีม debug ไม่ใช่คาสิโน / "ธรรมดา + ผิด" ยังจ่าย flat เดิม / บาลานซ์ EV ~107% (แย่กว่าตอบถูกมั่นใจเสมอ — เดาสุ่มไม่คุ้มกว่าตั้งใจตอบ) ตั้งค่าใน `CONFIG.fail_roulette` reuse `weightedPick`
- **กู้บั๊กด่วน (Debug Rescue, REV 1.7)**: มินิเกม 2 คน 2 มือถือสไตล์ Keep Talking — solver เห็นปริศนา (ตัดสายไฟ), guide เห็นกฎ, ห้ามดูจอกัน คุยด้วยปากเปล่า / **ไม่มี backend**: ทั้งคู่พิมพ์ "รหัสร่วม 4 ตัว" เป็น seed → derive ปริศนา+กฎ+เฉลยชุดเดียวกันแบบ deterministic (seeded PRNG) solver ตรวจผลเองได้ / route `?space=debug_rescue&role={solver|guide}&code=XXXX` / hint เผยกฎ+ตัดเวลา 30% / reward 200 penalty 100 (เบา ตามดีไซน์เน้นสนุกจากการสื่อสาร) / ตอนนี้เล่นได้ pattern `wire_cut` เต็ม อีก 3 pattern (keypad/command_match/final_boss) วางโครง config ไว้ (`enabled:false`)
- **แก้เสียงมือถือติดช้า (REV 1.8)**: `resume()` เป็น async แต่โค้ดเดิมทิ้งโน้ตถ้า context ยังไม่ running → เสียงแรก ๆ หายบนมือถือ — แก้เป็น schedule ต่อ + silent buffer warm-up (iOS) + unlock หลาย event
- **โหมดมั่นใจปรับใหม่ (REV 1.9)**: playtest พบไม่ต่างจากโหมดปกติ — เปลี่ยนเป็น เลือกโหมด**ก่อนเห็นคำถาม** / มั่นใจต้องผ่าน **modal ยืนยัน + countdown 5 วิ** (หมดเวลา/ยกเลิก = กลับเลือกใหม่ ไม่เสียสิทธิ์) / คำถามมั่นใจดึงจาก **L4 ชุดยากแยกต่างหาก** (25 วิ, ไม่ปนกับ logic อัปเกรด) / log เพิ่ม `question_level`
- **Bug Jam หลุดยากขึ้น (REV 2.0)**: playtest พบทุกคนหลุดหมดเพราะลองใหม่ฟรี — ตอบผิด/หมดเวลา = **เสียค่าปรับ** (ง่าย 300 / ยาก 500 + อดโบนัส) ห้ามตอบซ้ำในเทิร์น / **สลับตำแหน่งตัวเลือกทุกครั้ง** (กันจำตำแหน่งเฉลยตอนเล่นซ้ำในห้องเรียน) / เวลาตึงขึ้น: ง่าย 20 วิ ยาก 45 วิ / ปุ่ม "ยาก 💎" เปิดใช้จริงแล้ว (hard 4 ข้อ)
- **Cooling Zone → บอสไฟต์ทั้งวง (REV 2.1)**: จำลอง 12 รอบพบกติกาเดิม (คนหยุดคว้ากองกลางคนเดียว) ตัดสินผู้ชนะด้วยดวง 30% ของเกม — เปลี่ยนเป็น `?space=cooling`: **ทุกคนสแกนเข้าร่วม** เลือก "เลขรอบ" ที่คนหยุดประกาศ → seed ตรงกัน → โจทย์ตัดสายไฟชุดเดียวกันทุกเครื่อง (โหมด solo: เห็นกฎ+สายไฟบนจอตัวเอง, 75 วิ) / ใครผ่านแบ่งกองกลางเท่ากัน — **แผงธนาคาร**ประกาศสัดส่วน (0 คน = สะสมต่อ / 1 = ทั้งกอง / N = คนละ 1/N) เว็บไม่คำนวณเงินจริง / `bossfight_enabled: false` = กลับกติกาดั้งเดิม (ลดอิทธิพลดวง 55% → 32% ตามการจำลอง)

- **ราคาอัปเกรดชุดใหม่**: ทีม content ปรับสูตรเป็น **40% ของราคาซื้อ** (ลดจากเดิม ~20% ทุกช่อง เช่น coding_01 500→400, hardware_04 1250→1000) — ตัวเลขบนการ์ด REV 3.1 คำนวณจากสูตรเดียวกัน ตรงกับ `data.json` ครบทั้ง 16 ช่อง

### 6. ความทนต่อสถานการณ์จริงในห้องเรียน (REV 2.2)

ฟีเจอร์กลุ่มนี้ไม่เพิ่มกติกาเกม แต่แก้ปัญหาที่เจอเวลาเอาไปเล่นจริง:

- **กัน refresh หนีเวลา** (ช่องโหว่จริง — เด็กรีเฟรชกลางคำถามแล้วได้เวลาใหม่ฟรี): เก็บ `deadline` เป็นเวลาจริงลง `sessionStorage` พร้อมข้อคำถาม/ลำดับตัวเลือก/สถานะ hint → รีเฟรชแล้วได้**ข้อเดิม เวลาเดินต่อ** ครอบคำถามทรัพย์สิน/อัปเกรด/Bug Jam/Speed Event · ถ้าเวลาหมดไปแล้วค่อยเปิดกลับมา = เข้าสู่ flow หมดเวลาทันที (เสียค่าปรับ/หมุนวงล้อตามโหมด) · เลนมั่นใจ+ผิด **ต้องหมุนวงล้อจบก่อนถึงปิดเทิร์น** รีเฟรชหนีค่าปรับไม่ได้
- **ติดตั้งเป็นแอป + เล่นออฟไลน์ (PWA)**: เน็ตโรงเรียนล่มกลางคาบยังเล่นต่อได้ทุกหน้า — `sw.js` แคชตัวแอปแบบ cache-first (พร้อมอัปเดตเงียบเบื้องหลัง) และ `data.json` แบบ network-first, `manifest.webmanifest` + ไอคอน PCB 192/512 (`gen_icons.py`) ทำให้ "เพิ่มลงหน้าจอโฮม" ได้ · มีป้าย "⚡ โหมดออฟไลน์" มุมจอ
- **Wake Lock**: กันจอดับระหว่างจับเวลา ขอใหม่อัตโนมัติเมื่อสลับแอปกลับมา (เครื่องที่ไม่รองรับก็เล่นได้ปกติ)
- **หน้า error แทนจอขาว**: สแกน QR เบลอ/ผิดใบ → "❌ ไม่พบช่องนี้" พร้อมปุ่มสแกนใหม่/หน้าแรก · error ที่หลุดออกมาถูกดักด้วย `window.onerror` แสดงหน้าเริ่มใหม่ที่ล้าง session ให้
- **กันสแกนซ้ำในเทิร์นเดียว**: สแกนช่องเดิมซ้ำใน 90 วินาที → เตือนก่อน แต่มีปุ่ม **"ทำอีกครั้ง (ครูอนุญาต)" เสมอ** ไม่ล็อกตาย

### 7. บอสไฟต์วัดเนื้อหา + คำถามที่ตอบด้วยการ "ชี้" (REV 2.3)

**Cooling Zone: ตัดสายไฟ → Server Meltdown** (`CONFIG.cooling_boss.mode`)

กติกาเดิมมีช่องโหว่ 3 อย่าง: โจทย์ชุดเดียวกันทั้งโต๊ะ → ชำเลืองจอเพื่อนแล้วลอกได้ กองกลางกลายเป็นเงินแจก · เป็นโมเมนต์เงินก้อนใหญ่สุดของเกมแต่ไม่ได้วัดเนื้อหา 4 วิชาเลย (จุดอ่อนตอน defense) · ซ้ำกับ Debug Rescue ที่ใช้โจทย์ตัดสายไฟอยู่แล้ว

กติกาใหม่: บอสมี **HP ร่วมกันทั้งโต๊ะ** (จำนวนคน × 1.5) แต่ละคนรัวตอบคำถามบนมือถือตัวเอง **ตอบถูก 1 ข้อ = ฟันบอส 1 แต้ม** ใน 75 วินาที ถึงเป้า = แบ่งกองกลางตามสัดส่วนดาเมจ ไม่ถึง = กองกลางสะสมต่อ
- **กันลอกด้วย seed รายคน** `meltdown-{รอบ}-{จำนวนคน}-{เลขผู้เล่น}` → คำถามคนละชุด (วัดแล้ว: คำถามตำแหน่งเดียวกันตรงกัน 0/10 ข้อ) เชียร์กันได้เต็มที่แต่บอกเฉลยกันไม่ได้เพราะโจทย์ไม่ตรงกัน
- ตอบผิด = **ล็อก 5 วินาที** ("ระบบกำลังรีบูต") แทนตัดสิทธิ์ — กันกดมั่วรัว ๆ แต่ไม่ตกรอบกลางคัน
- ไม่มี realtime sync (ไม่มี backend) — แต่ละเครื่องนับดาเมจตัวเอง หมดเวลาแล้วตะโกนบอก Banker รวมกันที่โต๊ะ ความรู้สึก "สู้ร่วมกัน" มาจากเสียงในห้อง: ตอบถูกเด้ง `💥 โจมตี!` + เสียง + สั่น และมีป้ายค้างบนจอว่า "ตะโกนบอกเพื่อนทุกครั้งที่ฟันโดน!"
- โค้ดตัดสายไฟไม่ได้ลบ — `mode: 'wirecut'` สลับกลับได้เพื่อเทียบตอน defense และ `?space=debug_rescue` ยังใช้อยู่

**คำถามแบบชี้ตำแหน่ง 3 รูปแบบ** (เดิมทุกข้อเป็นตัวเลือกเหมือนกันหมด)
- `hotspot` — แตะตำแหน่งบนแผนผังเมนบอร์ด (SVG ฝัง inline จึงใช้ได้ตอนออฟไลน์) ตอบผิดขึ้นวงเฉลยเส้นประ + ชื่อชิ้นส่วน ใช้ 3 ข้อ: CPU Socket / สลอต RAM / ATX 24-pin
- `colorwheel` — แตะเสี้ยวสีบนวงล้อ 12 สี (สร้างจากโค้ด ไม่มีไฟล์ภาพ) ใช้กับโจทย์สีคู่ตรงข้าม ผ่อนผัน ±16°
- `linepick` — แตะบรรทัดโค้ดที่ผิด (monospace + `white-space:pre` เพราะโจทย์วัดเรื่องย่อหน้า) ตอบผิดไฮไลต์บรรทัดที่แตะแดง + บรรทัดเฉลยเขียว
- สถาปัตยกรรม: `renderQuiz` เป็นเจ้าของ timer/เสียง/เอฟเฟกต์ที่เดียว → เรียก `renderQuestion()` ที่ dispatch ตาม `qtype` **default ตกไปที่ตัวเลือกแบบเดิมเสมอ** ข้อมูลเพี้ยนก็ไม่จอขาว ทุกแบบให้ผลเหมือนกันเป๊ะ (ตอบถูกลด 20%)
- `build_data.py` ตรวจ 3 คอลัมน์ใหม่แบบ **fail ตั้งแต่ build** (ทดสอบ 14 เคส) — ข้อมูลผิดจะไม่ได้เขียน `data.json` เลย พร้อมบอก `question_id` + คอลัมน์ + ค่าที่เจอ

### 10. ระบบเก็บสถิติการเรียนรู้ (REV 2.5) — สำหรับบทที่ 4

เดิมมีแค่ hook เปล่า ๆ ที่ยิง `sendBeacon` ใบเดียวแบบไม่รู้ผล ตอนนี้เป็นระบบเก็บข้อมูลจริงที่ทนเน็ตโรงเรียนหลุดและแยกได้ว่า "ใครตอบข้อไหน ใช้เวลาเท่าไร เลือกตัวเลือกไหน"

**การส่ง** — `Logger` ใน `index.html`
- ทุกแถวเข้า **คิวใน localStorage** (`cc_log_queue`) ก่อนเสมอ แล้วค่อยยิง — เน็ตหลุดกลางคาบแล้วกลับมา แถวที่ค้างถูกส่งตามเอง (ยิงซ้ำตอน `online` / กลับมาเปิดแท็บ / โหลดหน้าใหม่) คิวสูงสุด 500 แถว เกินตัดแถวเก่าสุด ยิงทีละ 50 แถว
- ใช้ `fetch` อย่างเดียว **เลิกใช้ `sendBeacon`** เพราะ beacon คืน `false` เฉย ๆ เมื่อส่งไม่ออก ไม่ throw → โค้ดเดิมไม่มีทางรู้ว่าหาย และ fallback ไม่เคยทำงาน ระบบคิวต้องรู้ผลจริงถึงจะตัดแถวถูก
- ⚠️ **`Content-Type` ต้องเป็น `text/plain;charset=utf-8` เท่านั้น** — Apps Script ไม่ตอบ CORS preflight ถ้าใส่ `application/json` เบราว์เซอร์จะยิง `OPTIONS` ก่อน โดน 405 แล้ว log หายทั้งหมดโดยเกมไม่ error เลย
- ระบบ log พังยังไงเกมต้องเล่นต่อได้ — ทุก error ถูกกลืนหมด (localStorage เต็ม, JSON เสีย, fetch reject)
- สวิตช์: `log_url` ว่าง **หรือ** `log_enabled: false` = return ตั้งแต่บรรทัดแรก ไม่แตะ localStorage ไม่ยิงเน็ต

**ใครเป็นคนตอบ** — `Player` + `cc_player` (localStorage)
- ถามครั้งเดียว **คร่อมหน้าแรกที่เปิด ไม่ว่าจะสแกน QR เข้าหน้าไหน** (เกมไม่มีหน้าแรกที่ทุกคนต้องผ่าน) — กด "ข้ามไปก่อน" ได้ เล่นครบทุกอย่างเหมือนเดิม (`player` เป็น null)
- ปุ่มเล็กมุมขวาล่างทุกหน้า แก้เลขได้ตลอด — เปิดเป็น modal ลอย ไม่แตะหน้าที่เล่นอยู่ จึงกดกลางคำถามได้โดยเวลาตอบไม่สะดุด
- sync สองทางกับหน้าบอสไฟต์: เข้าไปแล้ว preselect ให้จากเลขเดิม เลือกใหม่ที่นั่นก็เขียนกลับ `cc_player` (ไม่แตะสูตร seed)
- เลขซ้ำกันในโต๊ะเป็น **ข้อความเตือนอย่างเดียว** — ไม่มี backend เช็คข้ามเครื่องไม่ได้จริง
- `cc_session` = id ประจำคาบ `YYYYMMDDHHmm-xxxx` ขาดช่วงเกิน 3 ชม. ออก id ใหม่ (คาบถัดไปแยกกลุ่มออกจากกัน) — เก็บใน localStorage ไม่ใช่ sessionStorage เพราะสแกน QR แต่ละครั้งเบราว์เซอร์มักเปิดแท็บใหม่

**เก็บอะไรบ้าง** — 10 จุดเรียก

| kind | เก็บตอนไหน | field เฉพาะทาง |
|---|---|---|
| `buy` / `buy_confident` | ตอบคำถามหน้าช่องทรัพย์สิน | `question_level` |
| `fail_roulette` | หมุนวงล้อหลังมั่นใจแล้วพลาด | `roulette_label`, `pay` |
| `upgrade` | ตอบคำถามอัปเกรด | — |
| `speed` | การ์ดแข่งตอบเร็ว (**log ทั้งตอนมีคนชนะและตอนไม่มีใครตอบ**) | `winner` |
| `bugjam` / `bugjam_hard` | แก้บั๊ก | `difficulty`, `hinted` |
| `debug_rescue` | มินิเกมตัดสายไฟ | `pattern`, `variant`, `hinted`, `cut_index` |
| `meltdown_q` 🆕 | **รายข้อ** ในบอสไฟต์ Server Meltdown | `round`, `player_slot`, `subject`, `q_index` |
| `cooling_boss` | สรุปบอสไฟต์ (แยกโหมดด้วย `mode`) | `damage`, `hp_target`, `questions_seen`, `wrong_count`, `subjects_hit`, `fight_duration_ms` |

ทุกแถวได้ field พื้นฐานอัตโนมัติ: `kind, space_id, level, correct, ts, session, player, elapsed_ms, row_id`
และแถวที่มีตัวคำถามได้เพิ่ม: `question_id, qtype, timed_out` + ค่าที่ผู้เล่นแตะ — `picked` + `picked_label` (MCQ) / `picked_xy` (hotspot) / `picked_deg` (colorwheel) / `picked_line` (linepick)

**กติกาข้อมูล 3 ข้อที่ตั้งใจทำ** (สำคัญตอนวิเคราะห์)
1. **`picked_label` ต้องมีคู่กับ `picked` เสมอ** — bugjam กับบอสไฟต์สลับตำแหน่งตัวเลือกรายเครื่อง `picked: 2` ของเด็กคนละคนจึงคนละตัวเลือก นับ distractor ยอดฮิตข้ามเครื่องได้ด้วย label เท่านั้น
2. **`elapsed_ms` ต้องแปลว่า "เวลาตอบข้อนั้น" เสมอ** — `fail_roulette` (ไม่ใช่การตอบคำถาม) และสรุปบอสไฟต์ (ความยาว 75 วิ) ถูกบังคับเป็น `null` ค่าความยาวบอสไฟต์ย้ายไป `fight_duration_ms` ถ้าปล่อยปนกัน ค่าเฉลี่ยตอน pivot จะพุ่งโดยไม่มีอะไรฟ้อง · `debug_rescue` กับ `cooling_boss(wirecut)` เป็น `null` ถาวรเพราะใช้ตัวจับเวลาแยก
3. **`meltdown_q` ห้ามใช้ kind `cooling_boss`** — ไม่งั้นยอดรวมรายบอสไฟต์จะถูกนับเบิ้ลกับแถวรายข้อ

**ที่ต้องทำต่อฝั่ง Apps Script**: body ที่ส่งไปเป็น **array ของแถว** (ไม่ใช่ object เดี่ยวแบบเดิม) — `JSON.parse(e.postData.contents)` แล้ววน `forEach` เขียนทีละแถว ใช้ `row_id` กันแถวซ้ำกรณียิงซ้ำ

### 11. ระบบ Motion / animation (Stage 1–4)

เว็บเดิมเปลี่ยนหน้าและเฉลยแบบตัดวืด ๆ ไม่มีจังหวะ — Stage 1–4 ใส่ระบบ animation ที่ **ไม่แตะ logic เกมและไม่ทำให้เวลาตอบเพี้ยน** รายละเอียดเต็ม (รวมกับดักที่เจอระหว่างทำ) อยู่ใน [`animation.md`](animation.md)

**Stage 1–2 — รากฐาน + นาฬิกา** (commit `ca652dd`)
- **Motion tokens** ใน `:root` (`--dur-press/enter/state/cheer`, `--ease-out/io/pop`) + `html[data-motion="on"|"off"]` override ทับมีเดียควีรีได้
- **`MOTION`** object — `reduced` มี 3 สถานะ (`on`/`off`/`null` = ตามเครื่อง), `run()` เก็บกวาด `will-change` ให้อัตโนมัติ · **`animShim()`** กันเบราว์เซอร์ที่ไม่มี WAAPI คืน `null` แล้วโค้ดที่ผูก `.onfinish` ต่อกันพังเป็นจอขาว · **`skippable()`** แตะจอที่ไหนก็จบ animation ทันที
- ปุ่ม 🐇/🐢 "ลดการเคลื่อนไหว" ข้างปุ่ม mute (เก็บใน `localStorage['cc_motion']`)
- **วงแหวนนาฬิกา** — SVG `stroke-dashoffset` ยิงผ่าน `el.animate()` ตรง ๆ ด้วย `duration = time_limit*1000` เสมอ **ไม่ผ่าน `MOTION.run()`** เพราะถ้าย่อเวลาได้เมื่อไร นาฬิกาจะโกหกเวลาจริง · รีเฟรชกลางคำถามเซ็ต `currentTime` ให้ตรงเวลาที่ผ่านไปจริง

**Stage 3 — จังหวะเฉลย** (commit `b2b3ea1`) ทำผ่าน delegation ล้วน **ไม่แตะ renderer ทั้ง 4 แบบ**
- **`renderToken`** ตัวนับ global +1 ทุกครั้งที่เข้าหน้าใหม่ — ทุก rAF loop และ WAAPI `onfinish` ต้องจับ token ตอนเริ่มแล้วเทียบก่อนแตะ DOM ทุกเฟรม (กัน animation ของหน้าเก่าไปเขียนทับหน้าใหม่)
- `playAnswerFx()` เรียกทันทีหลัง `logAnswer()`: ถูก = pop + วาดเครื่องหมายถูก, ผิด = shake + เฉลยข้อถูก fade เขียว · ตัวเลขเงินนับไต่ด้วย rAF + `tabular-nums` · ป้าย +/- ลอยขึ้นจาง

**Stage 4 — จังหวะรางวัล** (commit `de37963`)
- **Fail Roulette เขียนใหม่เป็นวงล้อ SVG จริง** — กฎเหล็กคือ **ผลต้องเกิดก่อน animation เสมอ**: `weightedPick()` → `Session.patch()` → `logAnswer()` → ค่อยหมุน (วงล้อเป็นแค่ของประดับ ไม่ตัดสินอะไร) · รีเฟรชกลางหมุนเด้งผลเดิมทันที ไม่สุ่มใหม่ ไม่ log ซ้ำ · reduced-motion ข้ามการหมุนไปแสดงผลเลย · แตะข้ามได้หลัง 1.0 วิเท่านั้น
- **การ์ดเหตุการณ์พลิก** — เฉพาะ mechanic `simple`/`choice`/`chain` · **`speed` ไม่มี cover เด็ดขาด** เพราะจับเวลา 15 วิ ต้องโผล่ที่ 0ms
- **จอสั่นตอนฟันบอส** + **HP bar เปลี่ยนจาก `width` เป็น `transform:scaleX()`** ตามกฎ transform-only

**กฎที่ยึดตลอดทั้งระบบ** (ห้ามแหก ไม่งั้นเวลาตอบเพี้ยนหรือจอขาว)
1. animate เฉพาะ `transform`/`opacity` (ยกเว้น `stroke-dashoffset` ที่วงแหวนนาฬิกา + เครื่องหมายถูก)
2. **ห้ามมี `await`/`setTimeout`/`.finished` คั่นระหว่าง `Session.done()` กับ `logAnswer()`** (ดูบั๊ก `elapsed_ms` รั่วในตารางข้างล่าง)
3. ห้ามแตะ `renderMCQ`/hotspot/colorwheel/linepick และ 2 จุดกันจอขาว (`return renderMCQ(...)` + กิ่ง "ไม่มีตัวเลือก")
4. ทุก rAF/onfinish ที่แตะ DOM ต้องเช็ค `renderToken` ก่อน
5. บั๊ม `CACHE` ใน `sw.js` ทุก Stage ที่แก้ `index.html`

## งานที่เหลือ

1. **เขียนคู่มือกติกาส่วน "จุดพักเครื่อง" ใหม่ทั้งหมด** — กติกาเปลี่ยน 2 รอบแล้ว (คนหยุดคว้ากองกลางคนเดียว → บอสไฟต์ตัดสายไฟ → **Server Meltdown**) คู่มือต้องมี: ค่าเข้าร่วม 200 ₮ จ่ายเข้ากองกลางก่อนเริ่ม · เป้าหมาย = จำนวนคน × 1.5 แต้ม ใน 75 วินาที · ทุกคนเลือก "เลขรอบ + จำนวนคน + เลขผู้เล่นของตัวเอง" ให้ตรงกันทั้งโต๊ะ (เลขผู้เล่นห้ามซ้ำ) · ตอบถูก 1 ข้อ = ฟัน 1 แต้ม ตอบผิดล็อก 5 วิ · หมดเวลาแล้วตะโกนบอกดาเมจให้ Banker รวม · ถึงเป้า = แบ่งกองกลาง**ตามสัดส่วนดาเมจ** ไม่ถึง = กองกลางสะสมต่อ
   - ⚠️ บนกระดานเขียนแค่ "บอสไฟต์! ทุกคนสแกนแข่ง / ผ่าน = แบ่งกองกลาง" — **ไม่ได้บอกค่าเข้าร่วม 200 ₮ และไม่ได้บอกว่าแบ่งตามสัดส่วน** ถ้าพื้นที่บนช่องไม่พอ ต้องอธิบายให้ชัดในคู่มือแทน
2. **ทีม content review hint ของ Bug Jam ระดับ hard 4 ข้อ** (bug_16–19) — ไฟล์ข้อมูลไม่ได้ส่ง hint มา ผมเขียนไว้ให้ก่อน / และแก้ไฟล์ต้นทาง 2 จุดที่พังซ้ำทุกรอบ: คอลัมน์ hint หาย + `office_02_L1_01` choice_b ต้องพิมพ์ `'= (เท่ากับ)` (apostrophe นำหน้า)
3. **Debug Rescue อีก 3 pattern** (keypad / command_match / final_boss) — config วางโครงไว้แล้ว (`enabled:false`) เสียบเพิ่มได้
4. **เก็บสถิติการตอบ (บทที่ 4)** — ฝั่งเว็บ **เสร็จแล้วทั้งหมด** (ดูหัวข้อ 10) เหลือ 2 อย่าง:
   - เขียน Apps Script รับ POST → `JSON.parse(e.postData.contents)` ได้ **array ของแถว** วน `forEach` เขียนลงชีต (dedupe ด้วย `row_id`) แล้ว deploy เป็น Web app สิทธิ์ "Anyone"
   - เอา URL `/exec` มาใส่ `CONFIG.log_url` (ตอนนี้เว้นว่างไว้ = ปิดระบบอยู่) แล้วบั๊ม `CACHE`
   - แนะนำให้ลองเก็บจริง 1 คาบก่อนใช้จริง แล้วเปิดชีตดูว่าคอลัมน์ครบตามหัวข้อ 10 ไหม
5. **ส่งโรงพิมพ์**: ไฟล์ใน `print/Final/` พร้อมแล้ว (ตรวจ QR บนกระดานครบ 6 ใบแล้ว) — สั่งพิมพ์ **Scale 100% / Actual size (ห้าม Fit to page)** ไม่งั้น QR จะเล็กลงจนสแกนยาก, เปิด Background graphics, การ์ดพิมพ์ 2 หน้าเลือก Flip on long edge ให้ตรงกับตัวเลือกบนหัวไฟล์
6. **กล่องเกม**: เคลียร์ 13 ข้อใน [`BOX_DEMO.md`](BOX_DEMO.md) ก่อนส่งพิมพ์กล่อง — ที่ต้องรีบสุดคือ **ตัวเลขจำนวนคำถามบน 3 แผงไม่ตรงกัน** (ของจริงคือ 81) และ **ยังไม่มีไฟล์ออกแบบธนบัตร/โทเค็น/คลิป** เลย
7. **Motion Stage 5 (ตรวจรับรอบสุดท้าย)** — ยังไม่ได้รัน รายละเอียดใน [`animation.md`](animation.md) ของที่ค้างอยู่:

   - `.fx-flash` / `#hit-fx` / `.result.pop` / `.countdown-big` ยังใช้ duration ตายตัว ไม่ผ่าน motion token (โค้ดเดิมตั้งแต่ก่อน Stage 1)

## หมายเหตุทางเทคนิค

- เครื่องนี้รัน Python ด้วย `py` (ไม่ใช่ `python`)
- **สคริปต์ที่มี shebang `#!/usr/bin/env python3` (`gen_demo_assets.py`, `make_standalone.py`) ต้องรันด้วย `py -3`** — `py` เฉย ๆ จะไปอ่าน shebang แล้ววิ่งไปหา `python3` ซึ่งบนเครื่องนี้เป็น alias ของ Microsoft Store แล้วเด้ง "Python was not found"
- ทดสอบในเครื่องผ่าน `py -m http.server 8000` **ที่รากโปรเจค** (fetch ไม่ทำงานบน `file://` และ Service Worker ต้องการ localhost/https)
- **แก้ `index.html` เมื่อไร ต้องบั๊ม `CACHE` ใน `sw.js`** (ตอนนี้ `codecoin-v17` → ครั้งหน้า `v18`) ไม่งั้นเครื่องที่เคยเปิดเว็บจะยังเห็นโค้ดเก่า — เจอกับตัวตอนเทสต์ REV 2.5: แก้ไฟล์แล้วแต่เบราว์เซอร์ยังรันโค้ดเก่าจากแคช ทำให้ผลเทสต์ผิด ต้อง unregister SW + `caches.delete()` ก่อนถึงจะเห็นของใหม่
- `core.autocrlf = true` บนเครื่องนี้ — ไฟล์ที่สคริปต์ Python เขียนออกมาเป็น CRLF แต่ git เก็บเป็น LF ให้เอง เจนไฟล์ใหม่แล้ว `git diff` ว่างเปล่าถือว่าปกติ (ไม่ใช่สคริปต์ไม่ทำงาน)
- ไฟล์ Excel จากทีม content: **diff ก่อน merge ทุกครั้ง** อย่าเอาทับตรง ๆ (รอบ qtype ล่าสุดสะอาด ไม่มี regression เป็นครั้งแรก)
- Push ต้อง login GitHub ใหม่แต่ละครั้ง (Windows Credential Store มีปัญหา เก็บ credential ถาวรไม่ได้) — ใช้ device flow: กรอกรหัสที่ github.com/login/device
- Repo เป็น public (เงื่อนไข GitHub Pages ฟรี) — เฉลยคำถามเปิดดูได้ถ้ารู้ที่อยู่ repo
- กติกาที่ห้ามเปลี่ยน: naming `{zone}_{ลำดับ 2 หลัก}`, รูปแบบ effect, ธีม PCB, UI ภาษาไทย
